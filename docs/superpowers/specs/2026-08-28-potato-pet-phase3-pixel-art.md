# Potato Pet — Phase 3: Pixel-Art Sprites Design Spec

**Date:** 2026-08-28
**Status:** Approved design, pre-implementation
**Parent spec:** `2026-08-27-potato-pet-design.md` (§5.1 world object, §8 interactions, §9 room, §14 art pipeline)
**Phases 1–2:** complete and merged to `main`. Game live at https://tato.forgesync.co.nz/; cloud sync built (off until `apiBase` is set).

---

## 1. Context and goal

The game currently renders the pet as a flat coloured `<div>` (`background: <colour>` + `filter: hue-rotate(<tint>deg)`), "animated" by CSS transform keyframes (`bob`, `wiggle`, `chomp`, `snooze`). Room decorations render as the first letter of the item's label in a grid cell. Room themes are flat background colours.

**Goal:** replace all placeholder visuals with real pixel-art sprites — an animated creature per species, tiled room floors/walls per theme, and a distinct sprite per decoration — while keeping the project zero-build and fully offline-capable, and while degrading cleanly to today's visuals if any asset is missing.

**Constraint that shapes everything:** the art is *generated by a committed Node script*, not sourced from third-party CC0 packs. Claude cannot browse asset sites or commit curated binaries; the maintainer did not want to hunt itch.io. So the sprites are hand-authored as pixel grids inside the generator and will be deliberately low-fidelity (recognisable blocky creatures, not detailed art). The generator's output is committed; it can be re-run to reproduce byte-identical files.

---

## 2. Decisions taken during brainstorming

1. **Art source:** a committed generator script produces all PNGs. No third-party assets. (Self-contained; low-fi accepted.)
2. **Scope:** both the pet AND the room (floor/wall tiles + decoration sprites). Full parent-spec §14 vision, in two implementation tracks (pet first, room second — see §9).
3. **Pet colour variety:** baked palette variants. The generator emits **4 hand-tuned recolours per species** (natural / warm / cool / pale). `world.pet.tint` (unchanged, `0–359`) selects one via `Math.floor(tint / 90)`. No save migration.
4. **No game-logic / save-shape / sync changes.** Purely the render path plus one committed tool and its output.

---

## 3. Architecture overview

```
  tools/gen-art.mjs   (committed dev tool, run by hand; node:zlib only, no npm)
    ├── indexed-PNG encoder  (~120 lines, deterministic — no timestamps)
    ├── pixel-grid authoring data  (per species / theme / decoration, in-script)
    ├── frame derivation  (bob / squash / mouth-toggle / sleep-flatten transforms)
    └── palette-variant recolour maps  (4 per species)
              │  writes
              ▼
  potato-pet/assets/sprites/
    pet/<species>-<0..3>.png     8 species × 4 variants; sheet = cols(frames) × rows(anims)
    room/floor-<theme>.png       4 themes, one tileable cell
    room/wall-<theme>.png        4 themes, one tileable cell
    deco/<id>.png                12 decorations, one transparent cell each
    LICENSE.txt                  "generated by tools/gen-art.mjs, CC0, no third-party assets"
              │  consumed by
              ▼
  potato-pet/js/sprites.js   manifest: cell size, cols, variants, sheet(v) path fn, anims{row,frames,fps}
              │
      ┌───────┴────────┐
      ▼                ▼
  js/pet.js         js/room.js
  frame-stepping     renderRoom: tiled floor/wall bg + deco sprite spans
  <div> renderer     (buy/place/bounds logic UNCHANGED)
      │                │
      ▼                ▼
  js/startscreen.js   js/gamescreen.js
  preview = idle       renderShop = deco icons beside buy buttons
  sprite frame
```

**Boundaries:**
- `tools/gen-art.mjs` and its test are dev-only, kept out of the front-end (pattern: same as `worker/`, `run-suite.mjs`). Their output — the PNGs — is what the game ships.
- `sprites.js` is the single source of sprite metadata. `pet.js` and `room.js` read it; nothing else does.
- No game module gains knowledge of PNG internals — they set `background-image` / `background-position` and step a timer.

## 4. Asset generation — `tools/gen-art.mjs`

### 4.1 Run model

`node tools/gen-art.mjs` (or `cd tools && npm run gen`) regenerates every file under `potato-pet/assets/sprites/`. It is **not** part of any build; it is run by hand when the art definitions change, and its output is committed (like `potato-pet/run-suite.mjs` is a committed dev tool). The front-end never runs it. Output paths are resolved relative to the script file (`new URL("../potato-pet/assets/sprites/", import.meta.url)`), not the cwd, so it works from either the repo root or `tools/`.

### 4.2 Authoring format

Each sprite is authored in-script as:

```js
{
  palette: { k: "#1a1a1a", b: "#e0a060", w: "#ffffff", /* … ≤ 15 named colours, "." = transparent */ },
  pixels: [
    "..kkkkkk..",
    ".kbbbbbbk.",
    "kbwbbbwbk",
    /* … equal-length strings, one char per logical pixel */
  ]
}
```

- Grids are square, **≤ 32×32 logical pixels** (24–28 typical, centred in a 32px cell).
- Palette per sprite, ≤ 15 entries + transparent → fits a 4-bit indexed PNG.

### 4.3 PNG encoder

A pure-JS **indexed-colour (`PLTE` + `tRNS`) PNG encoder**, ~120 lines:
- 8-bit indexed (`colour type 3`), one `PLTE` chunk from the sprite's palette, `tRNS` marking the transparent index.
- Scanlines with filter byte `0` (none); `IDAT` compressed with `node:zlib`'s `deflateSync` at a fixed level.
- CRC-32 over each chunk (small table, computed once).
- **No timestamps, no `tIME`, fixed deflate level** → running the script twice yields byte-identical files.

### 4.4 Pet sheets — `pet/<species>-<v>.png`

- 8 species (`strawberry broccoli turtle cat frog donut carrot penguin`) × 4 variants `v ∈ 0..3`.
- Sheet layout: **columns = animation frames, rows = animations**. Rows in order: `idle`, `happy`, `eat`, `sleep`. Cell = **32×32**. Authored frames per row = 2 → sheet is `2*32` wide × `4*32` tall = **64×128**.
- One base sprite authored per species. The other frame(s) and the non-idle rows are **derived** by transforms:
  - `idle` frame 2 = base shifted up 1px (bob).
  - `happy` = base with a 1px vertical squash + 1px horizontal stretch on frame 2.
  - `eat` = base with a mouth-row pixel pair toggled open/closed between frames.
  - `sleep` = base flattened ~30%, eyes → closed line, a small `z` glyph pixel-drawn top-right; frame 2 nudges the `z`.
- **Palette variants:** 4 recolour maps per species (`natural`, `warm`, `cool`, `pale`) applied to the authored palette before encoding. Each variant is its own file.

### 4.5 Room tiles — `room/floor-<theme>.png`, `room/wall-<theme>.png`

- 4 themes (`meadow bedroom space beach`). One **32×32 tileable cell** per file (edges designed to repeat seamlessly). Floor = ground texture; wall = the strip shown behind the top grid row.

### 4.6 Decoration sprites — `deco/<id>.png`

- One per catalog `id` (12: `rug lamp plant poster beanbag bookshelf window ball blocks clock table cushion`). **32×32, transparent background**, the object centred.

### 4.7 LICENSE.txt

Replaced with: all sprites generated by `tools/gen-art.mjs`; released CC0 / public domain; no third-party assets are used or redistributed.

## 5. `js/sprites.js` — new manifest

Replaces the current `{ placeholderColor, anims: { name: { frames, fps } } }` shape.

```js
App.sprites = (function () {
  const COLORS = { /* unchanged 8-species hex map — kept for the fallback block */ };
  const CELL = 32, COLS = 2, VARIANTS = 4;
  const ANIMS = {
    idle:  { row: 0, frames: 2, fps: 2 },
    happy: { row: 1, frames: 2, fps: 8 },
    eat:   { row: 2, frames: 2, fps: 6 },
    sleep: { row: 3, frames: 2, fps: 1 },
  };
  const manifest = {};
  App.world.SPECIES.forEach(s => {
    manifest[s] = {
      cell: CELL, cols: COLS, variants: VARIANTS,
      rows: Object.keys(ANIMS).length,
      placeholderColor: COLORS[s] || "#999",
      sheet: v => "assets/sprites/pet/" + s + "-" + v + ".png",
      anims: ANIMS,
    };
  });
  function animFor(species, name) {
    const m = manifest[species];
    const a = (m && m.anims) || ANIMS;
    return a[name] || a.idle;
  }
  function variantFor(tint) {
    const t = (typeof tint === "number" && isFinite(tint)) ? tint : 0;
    return ((Math.floor(t / 90) % VARIANTS) + VARIANTS) % VARIANTS;
  }
  return { manifest, animFor, variantFor, CELL, COLS, VARIANTS };
})();
```

- `animFor` contract unchanged: unknown species or unknown anim → a valid `idle` def, never throws. `peek` is no longer a row → falls back to `idle`; the peek *visual* stays as the CSS `.anim-peek { opacity:.5 }` rule.
- `variantFor` is total and wraps: negatives, `NaN`, `undefined`, `> 359`, `>= 360` all map into `0..3`.

## 6. `js/pet.js` — frame-stepping renderer

Public contract unchanged: `mount(container, world)`, `render(mood)`, `playAnim(name, done?)`, `speak(text, ms?)`.

### mount
```
scale = 3   // 32px cell → 96px on screen
build: <div class="stage">
         <div class="speech" hidden></div>
         <div class="pet pixel" data-mood="happy"></div>
       </div>
el.style.width  = el.style.height = (CELL*scale) + "px";
const v = App.sprites.variantFor(world.pet.tint);
const src = App.sprites.manifest[species].sheet(v);
preload src via new Image():
  onload  → el.style.backgroundImage = "url(" + src + ")";
           // scale the whole sheet: sheet is (COLS*CELL) wide by (rows*CELL) tall
           el.style.backgroundSize = (COLS*CELL*scale) + "px " + (rows*CELL*scale) + "px";
           el.dataset.ready = "1";
  onerror → el.classList.add("fallback");
           el.style.background = manifest[species].placeholderColor;
           console.warn("sprite sheet failed: " + src);
start ambient anim = idle (see render)
```

### render(mood)
- `el.setAttribute("data-mood", mood)` (CSS still dims/tints hungry/sleepy/bored, keeps the subtle `snooze` drift).
- Ambient animation: `mood === "sleepy"` → loop `sleep`; else → loop `idle`. Implemented by `setAmbient(name)` which starts a repeating frame stepper (see below) that a one-shot `playAnim` temporarily overrides.

### playAnim(name, done)
- `if (!el || el.classList.contains("fallback")) { done && done(); return; }`
- `const a = App.sprites.animFor(species, name)`.
- Stop the ambient stepper. Run a **frame stepper**: `setInterval` every `1000/a.fps` ms, advancing `col = (col+1) % a.frames`, setting
  `el.style.backgroundPositionX = -(col * CELL * scale) + "px"` and
  `el.style.backgroundPositionY = -(a.row * CELL * scale) + "px"`.
- Duration budget = `Math.max(400, (a.frames / a.fps) * 1000)` (same formula as today). After it elapses: clear the interval, restore the ambient stepper, `done && done()`.
- Looping ambient anims (`idle`, `sleep`) use the same stepper with no duration budget.
- All timers tracked in module scope and cleared on a new `mount` / new `playAnim` so they never stack.

### styles.css
- `.pet`: drop `border-radius`, `background`, and the `bob` animation. Keep `data-mood` opacity/filter rules and `.pet.anim-peek { opacity:.5 }`. Add `background-repeat: no-repeat`. `.pet.fallback` re-adds `border-radius:24px`.
- Remove the now-unused `@keyframes bob` / `@keyframes chomp` and `.pet.anim-eat` (frame-stepping replaces them). Keep `@keyframes wiggle` (used by `data-mood="bored"`) and `@keyframes snooze`.
- `.preview` (creation screen): sized to the sprite, `image-rendering: pixelated`, no flat colour / border-radius.

## 7. `js/startscreen.js` — creation preview

The preview step currently renders `<div class="preview pixel" style="background:<placeholderColor>;filter:hue-rotate(<tint>deg)">`. It becomes the pet's **idle frame**:

```
const v = App.sprites.variantFor(preview.pet.tint);
const m = App.sprites.manifest[preview.pet.species];
const S = 3;  // preview scale
// background-size = whole sheet scaled: (m.cols*m.cell*S) x (m.rows*m.cell*S)
'<div class="preview pixel" style="background-image:url(' + m.sheet(v) +
  ');background-size:' + (m.cols*m.cell*S) + 'px ' + (m.rows*m.cell*S) + 'px' +
  ';background-position:0 0"></div>'
```
The `.preview` div sizes to `m.cell*S` square, so it shows the idle row's first frame. Fallback: a sibling probe `new Image()` on the sheet URL flips the div to the flat `placeholderColor` block on error (same degradation as `pet.js`). No behavioural change to the reroll / keep / name flow. `randomCode` etc. untouched.

## 8. `js/room.js` + `js/gamescreen.js` — room rendering

**`room.js` — only `renderRoom` changes.** All of `CATALOG`, `priceOf`, `canBuy`, `buy`, `cellOccupied`, `place`, `pickUp` and their `room.tests.js` coverage are untouched.

`renderRoom(container, world, opts)`:
- Container markup: `<div class="room theme-<theme>">` + a `<div class="wall">` strip + the 12×8 `<button class="cell">` grid (unchanged button attributes `data-x` / `data-y`, unchanged `placeMode` / `onPlaceCell` wiring).
- The `.room` gets `background-image: url(assets/sprites/room/floor-<theme>.png)`, `background-size: <cellpx>px`, `image-rendering: pixelated`, so the floor tiles across.
- `.wall` gets `background-image: url(assets/sprites/room/wall-<theme>.png)` tiled horizontally.
- A placed decoration: `<span class="deco pixel" data-item="<id>" style="background-image:url(assets/sprites/deco/<id>.png)">L</span>` where `L` is the label's first letter kept as textContent (shown only if the image fails — CSS layers the background over the text; an `onerror` on a probe `Image()` or a CSS class toggle reveals the letter).
- Missing floor/wall sheet → the flat `.room.theme-*` background colour underneath shows (kept in CSS as a fallback declaration on the same rule).

**`gamescreen.js` — `renderShop`.** Each catalog buy button gains a small `<span class="shopicon pixel" style="background-image:url(assets/sprites/deco/<id>.png)">` before the label. Label text and the buy/price logic are unchanged.

**`styles.css` room block:**
- `.room` / `.room.theme-*`: `background: <flatcolour>;` stays as fallback; add `background-image`, `background-size`, `image-rendering: pixelated` (the image wins when it loads).
- `.cell` background → transparent (floor shows through); keep the border.
- `.deco`: drop `font-weight`; add `background-size: contain; background-repeat: no-repeat; background-position: center; color: transparent;` with a `.deco.noimg { color: inherit }` for the fallback.
- New `.wall`, `.shopicon` rules (fixed size, `pixelated`, `no-repeat`).

## 9. Sequencing & fallbacks

**Two tracks; pet first.** The implementation plan orders tasks so the **pet track** is complete and independently shippable before the **room track** begins:

- **Pet track:** PNG encoder + `gen-art.mjs` core + pet sheets + `sprites.js` + `pet.js` + `startscreen.js` preview + `sprites.tests.js` + `gen-art.test.mjs` (encoder & pet-output parts).
- **Room track:** theme tiles + deco sprites in `gen-art.mjs` + `room.js` `renderRoom` + `gamescreen.js` shop icons + `styles.css` room block + `gen-art.test.mjs` (room/deco output parts) + `TESTING.md` room section.

If the generated pet art is judged too poor at the pet-track review, the room track can be dropped without rework; the pet track leaves the game fully working.

**Fallbacks are permanent, not scaffolding.** Every asset load has a defined degradation to the *current Phase 2 visual*:
| Asset missing/broken | Degrades to |
|---|---|
| `pet/<species>-<v>.png` | flat `placeholderColor` block, no frame stepping |
| `deco/<id>.png` | the item's first-letter `<span>` (today's look) |
| `room/floor|wall-<theme>.png` | the flat `.room.theme-*` background colour |

No asset failure ever produces a blank element or a console error beyond a single `console.warn`.

## 10. Testing

### New: `potato-pet/js/sprites.tests.js`
Added to the module/test lists in `potato-pet/tests.html` and `potato-pet/run-suite.mjs`.
- `manifest` has an entry for every `App.world.SPECIES`; each has `cell === 32`, `cols === 2`, `variants === 4`, `rows === 4`, a `placeholderColor`, and `typeof sheet === "function"` with `sheet(2) === "assets/sprites/pet/<species>-2.png"`.
- `anims.idle/happy/eat/sleep` each have numeric `row`, `frames`, `fps`; `row` values are `0,1,2,3`.
- `animFor(s,"idle")` returns the idle def; `animFor(s,"peek")`, `animFor(s,"zzz")`, `animFor("nope","idle")` all return a def deep-equal to `idle` (no throw).
- `variantFor`: `0→0`, `89→0`, `90→1`, `270→3`, `359→3`, `360→0`, `-90→3`, `NaN→0`, `undefined→0`, `"x"→0`.

### New: `tools/gen-art.test.mjs` (Node `node --test`, dev-only, not in the front-end suite)
- **Encoder:** output starts with the PNG signature `89 50 4E 47 0D 0A 1A 0A`; `IHDR` decodes to the expected width/height, bit depth 8, colour type 3; `zlib.inflateSync` on the concatenated `IDAT` yields the expected filtered scanlines for a hand-checked 4×4 bitmap; every chunk's CRC validates.
- **Determinism:** run `gen-art.mjs` (into a temp dir) twice → every output file byte-identical.
- **Completeness:** after a run, every path `sprites.js` can request exists and is a valid non-empty PNG: `pet/<species>-<0..3>.png` (32 files), `room/floor-<theme>.png` + `room/wall-<theme>.png` (8), `deco/<id>.png` (12).

### Unchanged suites must stay green
`node potato-pet/run-suite.mjs` (currently 1248) and `cd worker && npm test` (10). `sprites.js`'s consumers (`pet.js`, `startscreen.js`) have no unit tests by prior ruling; the manifest shape is pinned by the new `sprites.tests.js`, and rendering is covered manually.

### Manual — appended to `potato-pet/TESTING.md`
1. For 2–3 species, load the same species with codes that yield different `tint` — confirm visibly different palette variants.
2. Idle bob visible; feed → `eat` frames play then return to idle; put to bed → `sleep` frames + dimming; hide-and-seek → peek dims the pet.
3. Each of the 4 room themes shows a tiled floor and a wall strip.
4. Buy + place each of the 12 decorations → its sprite appears in the cell; shop buttons show the matching icon.
5. Rename `potato-pet/assets/sprites/pet/cat-0.png` → reload a `cat` pet → coloured-block fallback, one `console.warn`, no error overlay. Restore the file.
6. Same for a `deco/*.png` (letter fallback) and a `room/floor-*.png` (flat colour fallback).

## 12. Out of scope

- No animation editor, no runtime/canvas sprite generation — all baked at author time by `gen-art.mjs`.
- No per-mood face sprites — mood stays a CSS treatment over the idle frames.
- No new species, themes, or catalog items.
- No sound.
- No change to game logic, `world` shape, save/migration, or the sync layer.
- No third-party asset sourcing or redistribution.
- Sprite art quality is explicitly "recognisable and low-fi", not detailed — the generator route was chosen with that trade-off accepted.
